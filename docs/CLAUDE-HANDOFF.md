## Продукт та незмінні вимоги

- Повноцінний native macOS-застосунок для Apple M1 / 16 GB / macOS 14.5. Користувач представить продукт на фінальному хакатоні приблизно через півтора тижні. Спеціальні критерії конкурсу невідомі.
- Спілкуйся з користувачем українською. Застосунок підтримує тільки українську й англійську. Російської немає в UI, ASR, TTS, тестових фразах або режимах. Заборонено необмежене автоматичне визначення мови ASR.
- Фраза активації саме **Jarvis**, не Hey Jarvis. Локальний детектор після явного ввімкнення користувачем; завжди видимий повний вимикач мікрофона. PTT залишається резервом. Це замінює стару вимогу «лише PTT».
- Аудіо не передається в хмару й не зберігається за замовчуванням. Виняток — вже реалізована явна одноразова діагностика WAV.
- Хмара допускається лише для складних текстових запитів, загальний місячний бюджет API до $10. Для простих локальних дій LLM не потрібна.
- Ніяких вигаданих результатів виконання. Відправлення повідомлень, видалення, покупки потребують конкретного підтвердження. Наявні конектори в чаті не означають доступність цих інтеграцій у застосунку.

## Що реально є зараз

Нативний AppKit-прототип `dist/Jarvis Voice Lab.app`, bundle ID `local.jarvis.voicelab`. На момент передачі немає реалізованого ARC Current, wake word, TTS, виконавця дій macOS чи інтегрованого Goose.

| Файл | Призначення |
|---|---|
| `Sources/App.swift` | AppKit UI, LocalSpeech, моделі, hotkeys, сесії, вимірювання, діагностика |
| `Sources/Audio.swift` | CaptureGate, AVAudioEngine, перетворення до float32 mono 16 kHz, обмеження запису |
| `Sources/Parakeet.swift` | Нативний CoreML TDT-декодер, UK/EN, обмежений цикл, cancellation |
| `Sources/WhisperBridge.cpp` та `.h` | Резервний whisper.cpp C bridge |
| `Sources/Measurement.swift` | Версійовані фрази й прогрес вимірювань |
| `Sources/Diagnostic.swift` | Одноразове збереження точного входу ASR у WAV |
| `Sources/Benchmark.swift` | CLI-перевірка моделі на WAV |
| `scripts/build.sh` | Компіляція, тести, збірка app bundle, ad-hoc підпис |

PTT: **Control+Option+Space**, утримання записує, відпускання розпізнає. Esc / Control+Option+Esc та кнопка скасовують. Не запускати захоплення на старті застосунку чи відразу після видачі дозволу. Поточний CaptureGate вимагає нового натискання; повтор клавіші після cancel не повинен запускати запис заново.

Parakeet UK — модель за замовчуванням; максимум 15 секунд, Whisper — 30. Модель резидентна, inference на послідовній черзі, старі результати скасованих сесій відкидаються. У `AudioCapture` поки немає API рівня звуку: його потрібно додати без другого незалежного захоплення мікрофона.

Збережи доступ до вимірювань, копіювання тексту, вибору UK/EN та одноразової діагностики. Їх можна винести з головного екрана в панель діагностики. Не перезаписуй історичні журнали: поточний `.runtime/measurements/uk-en-v1.jsonl`, старий `measurements.jsonl` зберігається окремо.

## Затверджений дизайн: ARC Current

Головний референс: `docs/design/jarvis-arc-current.png`. Це статичний концепт, не screenshot готового UI. ARC Neural, ARC Synapse, ARC Nexus, PRISM та початковий ARC не затверджені для реалізації.

- Темне синьо-чорне скло, тонкі контури, бірюзове світіння та стримані бурштинові імпульси. Чіткі українські підписи, читабельна типографіка.
- Ліворуч навігація; зверху бренд JARVIS та фактичний стан локальної роботи.
- Центральний образ — **горизонтальний потік тонких світлових ниток / голосових хвиль із нейронними імпульсами**, а не сфера, кільця або спіраль.
- Нижче великий текст поточного запиту, горизонтальний список справжніх кроків виконання, поле вводу та помітне «Вимкнути мікрофон».
- Компактний плаваючий HUD повторює хвилю та поточний стан, має cancel/mic-off і не перехоплює фокус поля, у яке диктує користувач.
- Відтворити композицію й матеріали нативними засобами. Не вставляти PNG як фон, який удає робочий застосунок. Не копіювати намальований Dock/робочий стіл усередину вікна.
- До появи справжнього виконавця не показувати завершені «Програми / Вікна / Фокус». Порожній стан або пояснення доступних можливостей краще за фальшивий прогрес.

## Перший етап: обсяг реалізації

Результат: застосунок збирається та відкривається на цьому Mac, має ARC Current main window і компактний HUD, реагує на реальний звук під час PTT та показує реальний результат наявного Parakeet. Не залишати лише макет чи ізольовану анімацію.

### 1. Єдиний стан застосунку

Виділи спільну модель стану для головного вікна, HUD та меню. Мінімум: microphoneDisabled, ready, recording, transcribing, result, error; стан завантаження моделі теж має бути явним. Передбач майбутні wakeListening / executing / speaking, але не показуй їх як працюючі можливості до інтеграції.

Потік: свіжий PTT press → recording → release → transcribing → result; cancel / mic-off / sleep / inactive session припиняє захоплення та інвалідовує поточний turn. Збережи захист від запізнілих callback. UI змінюється на main thread, inference і обчислення спектра — поза ним.

### 2. Справжні аудіометрики

Додай bounded-потік метрик із наявного AudioCapture: RMS/peak, згладжений envelope, за потреби невелика кількість частотних смуг. На realtime callback не виконувати рендер, FFT, файлові операції чи необмежене створення задач. Доставляй UI останній snapshot з обмеженою частотою; не створюй чергу на кожен семпл. Не змінюй точний буфер, який отримує ASR.

Після stop/cancel/reset рівень переходить до нуля; callback попередньої сесії не оживляє нову. Тиша, NaN, відсутній пристрій та зміна input device мають оброблятися без зависання.

### 3. Native ARC Current renderer

Вибери сумісний з macOS 14.5 спосіб: SwiftUI Canvas у NSHostingView, AppKit/Core Animation або Metal, залежно від реальної складності. Не мігруй весь застосунок у web/Electron. Залиш робочий прямий Swift build, якщо перехід на пакет не дає доведеної користі.

Хвиля з кількох шарів тонких ниток, контрольований glow, невеликі імпульси. Амплітуда й енергія в режимі recording залежать від реального мікрофона. Декоративний повільний рух допустимий, але не повинен удавати розпізнавання мовлення. Обробка запиту має інший впізнаваний рух та текстовий стан. Mic-off — однозначно неактивний.

Ціль 60 FPS, fallback 30 FPS за потреби; це ціль, не обіцянка. Зменшувати/зупиняти рендер у прихованому вікні, не витрачати ресурси на повну анімацію в idle. Поважати Reduce Motion; не покладатися лише на колір.

### 4. Оболонка та інтеграція

Реалізуй масштабоване main window, навігацію, текст запиту, реальні стани/помилки, mic-off, cancel, вибір UK/EN, доступ до діагностики. Недоступні функції явно позначені, не створюй фальшиві інтерактивні кнопки. Не симулюй виконання текстового запиту, поки немає executor.

Додай компактний HUD та меню стану. Якщо застосунок залишається в menu bar після закриття головного вікна, зміни нинішнє `applicationShouldTerminateAfterLastWindowClosed == true` свідомо; Quit мусить зупинити аудіо та очистити таймери. Не запускати wake listening приховано. Показ HUD не повинен активувати застосунок поверх цільового поля.

Нові Swift-файли додай у явний список компіляції `scripts/build.sh`. Залиш чинний bundle ID на цьому етапі, щоб без потреби не міняти дозволи macOS. Опис доступу до мікрофона онови, коли справді додаси wake word.

### 5. Коротка перевірка майбутнього runtime

Окремо від UI можна перевірити pinned Goose на macOS 14.5: запуск, custom-client transport/ACP, streaming, cancel, approval events, облік вартості. Не блокуй на цьому робочий ARC Current + PTT. Запиши фактичний go/no-go або конкретні невідомі до другого дня; не називай інтеграцію готовою після читання README.

## Критерії готовності першого етапу

1. `bash scripts/build.sh` проходить; наявні meaningful тести не видалені й не послаблені.
2. App запускається на macOS 14.5; на старті немає запису. Є ARC Current main window і HUD, UI не зависає під час ASR.
3. Реальний PTT запис дає видиму реакцію хвиль; тиша не малює випадкове «мовлення»; release дає реальну транскрипцію Parakeet.
4. Cancel, повний mic-off, timeout, відмова в дозволі, помилка моделі та закриття/quit не залишають capture або застарілу анімацію.
5. HUD не забирає фокус; Reduce Motion та приховування вікна не залишають зайвий активний renderer.
6. Вимірювання й одноразова WAV-діагностика залишаються доступними; аудіо не потрапляє в логи чи хмару.
7. Додані тести переходів стану, stale callbacks і метрик аудіо, де є нова логіка. Візуальну якість перевірено фактичним запуском і screenshot, не лише компіляцією.
8. Звіт містить змінені файли, виконані перевірки, невиконані перевірки/обмеження та команду запуску. Якщо live-мікрофон не перевірено, прямо це зазнач.

Не називай перший етап готовим, якщо є лише статична картинка або анімація без інтеграції з поточним ASR.

## Технічні пастки та докази

- Swift 6.0.3 CLT має конфлікт SwiftBridging module maps. `build.sh` уже створює project-local VFS overlay. Не редагуй системний SDK і не видаляй workaround навмання.
- SwiftPM раніше мав PackageDescription mismatch. Поточний прямий `swiftc` працює; нова залежність потребує реального smoke test.
- CoreGraphics потрібен CLI Metal initialization; без нього whisper.cpp CLI падав через nil MTL device. Збережи framework.
- Whisper pinned v1.8.3; точний фактичний commit перевір у `.runtime/whisper.cpp` перед зміною залежності. Поточні build/setup scripts є джерелом істини.
- Parakeet: `ihnatov-yuri/parakeet-tdt-0.6b-v3-uk`, revision `5c4bcfaca501587beaedfd23b72a678bf7194de1`, локально `.runtime/parakeet-probe/model/parakeet-tdt-0.6b-v3`. CoreML int8, приблизно 613 MB, ліцензія моделі CC BY 4.0; атрибуція в THIRD_PARTY.md. Не приписуй навчання моделі нашій команді.
- На одному підтвердженому українському записі Parakeet правильно розпізнав «Перемкнись на термінал.» 3/3, warm ~330–457 ms. Це не доказ загальної точності або end-to-end SLA. Whisper base/small і більші випробувані Whisper варіанти на цьому голосі помилялись; не повертай їх як default без нових доказів.
- Фільтр алфавіту UK/EN не гарантує визначення мови для спільних слів. Не заявляй неможливість чужої мови як доведену властивість.
- Повна збірка містить тести завантаження моделей. Metal/CoreML можуть вимагати запуску поза sandbox; відрізняй sandbox failure від дефекту коду.
- Bundle зараз ad-hoc signed і містить `JarvisProjectRoot` до checkout. Самодостатнє пакування — обов'язкове до релізу, але ще не зроблене.

## Наступні етапи, щоб не втратити архітектуру

- День 2: локальний wake word Jarvis, видимий off/PTT, рішення щодо Goose. Кандидат — sherpa-onnx KWS English-only Zipformer int8; це ще не перевірена інтеграція. Перевір точні токени, native linking на 14.5, ліцензію model artifact та голос користувача. Деталі: `docs/research/wakeword-jarvis-macos.md`.
- Дні 3–4: typed actions для програм/вікон/URL/диктування, фокус і справжні результати.
- Дні 5–6: складні текстові запити, approvals, бюджет, UK/EN TTS, одна фонова інтеграція. Аудіо залишається локальним.
- День 7: налаштування, історія, onboarding, offline/permission errors; feature freeze.
- Дні 8–9: реальні голосові/noise/cancel/довгі тести, ресурси, installable package.
- Дні 10–11: release candidate, репетиція, презентація, тільки виправлення.

Сервер користувача перевірявся через SSH alias `homeserver`: Windows 10 Home, Ryzen 5 2500U, ~15 GB RAM, RX560 ~4 GB, Wi-Fi. Він може виконувати фонові роботи, але не доведено, що прискорить ASR/LLM. Не став його в критичний голосовий шлях і не змінюй його сервіси як побічний ефект UI-роботи.

Корисні дослідження: `docs/research/2026-11-10-build-vs-adapt.md`, `docs/research/2026-11-10-asr-replacement.md`, `docs/research/parakeet-probe.md`, `docs/research/isair-jarvis-fit.md`. Goose — кандидат Apache-2.0; isair/jarvis має інші ліцензійні й архітектурні обмеження. Перевіряй ліцензії окремо для коду, моделей та залежностей.
