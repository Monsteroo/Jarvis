# Локальний підпис Jarvis

Навіщо: без сертифіката кожна збірка підписується «ad-hoc», і macOS вважає її новою програмою — після кожної перезбірки питає дозвіл на ключі ElevenLabs/OpenAI у Keychain. Зі сталим локальним сертифікатом «Дозволяти завжди» зберігається.

Сертифікат локальний і самопідписаний: він не дає права розповсюджувати застосунок і не змінює налаштувань безпеки системи. Його не треба позначати як довірений.

## Один раз створити сертифікат

1. Відкрийте програму «Ключар» (Keychain Access; «Програми → Утиліти») або командою `open -a "Keychain Access"`.
2. Меню «Ключар» (поруч з ) → «Асистент сертифікації» → «Створити сертифікат…»
   (Keychain Access → Certificate Assistant → Create a Certificate…).
3. Заповніть:
   - Назва (Name): `Jarvis Local Signing` — саме так, з великих літер;
   - Тип ідентичності (Identity Type): «Самопідписаний кореневий» (Self-Signed Root);
   - Тип сертифіката (Certificate Type): «Підписування коду» (Code Signing).
4. «Створити» → «Готово». Сертифікат з’явиться у в’язці «login».

## Після цього

- Наступна збірка напише `Signed with local identity: Jarvis Local Signing`.
- Перший раз macOS запитає, чи може `codesign` користуватися ключем сертифіката, — «Дозволяти завжди».
- Перший запуск нової збірки ще раз запитає доступ до ключів ElevenLabs і OpenAI — «Дозволяти завжди». Далі перезбірки вже не питатимуть.

Інша назва сертифіката: `JARVIS_SIGN_IDENTITY="Моя назва" bash scripts/build.sh`. Без сертифіката збірка, як і раніше, підписується ad-hoc.

Видалити: «Ключар» → «Мої сертифікати» → `Jarvis Local Signing` → Delete.
