# Existing macOS assistants: fork or a small native shell?

Researched 2026-11-07. Target: M1 / 16 GB / **macOS 14.5 unchanged**, mixed Ukrainian/Russian/English, microphone active only while the key is held, local audio processing, optional text-only cloud reasoning under a $10/month cap, allowlisted actions, explicit approval before every send. No applications, models, dependencies, or settings were installed or changed. This is a source review, not a runtime benchmark or complete security audit.

## Decision

**Build a small Swift/AppKit shell and reuse carefully selected, attributed components. Do not adopt any of these complete assistants unchanged.** Murmur is the strongest functional reference, but its current build requires newer tooling than the fixed target machine supports, and its broad memory/indexing/automation scope adds work unrelated to the first version. Cursor Voice and Samuel send microphone audio to cloud models, so they fail the clarified local-audio requirement. No reviewed project demonstrates mixed UK/RU/EN accuracy plus release-to-action latency ≤2 seconds on this exact M1/14.5 configuration.

This conclusion is engineering judgment based on the primary-source evidence below. A declared deployment target is evidence of intent, not proof that the released binary and all dependencies work on 14.5.

## Murmur — closest reference, substantial fork work

The application behind [usemurmur.live](https://usemurmur.live/) is **[shubhamsWEB/murmur-app](https://github.com/shubhamsWEB/murmur-app)**, not one of several unrelated repositories named Murmur. The website's shipped JavaScript links to this repository, and the repository links back. Source snapshot: `c9b1c91bd6a5affd43c5624e929ffbfa1eeb0cc8`; [MIT license](https://github.com/shubhamsWEB/murmur-app/blob/c9b1c91bd6a5affd43c5624e929ffbfa1eeb0cc8/LICENSE).

**Verified in source:** [Package.swift](https://github.com/shubhamsWEB/murmur-app/blob/c9b1c91bd6a5affd43c5624e929ffbfa1eeb0cc8/Package.swift) declares macOS 14, Swift tools 6.2, FluidAudio 0.17.7, WhisperKit 1.1.1, and separate VoiceKit, AgentKit, index, and background-memory components. Its [README build requirements](https://github.com/shubhamsWEB/murmur-app/blob/c9b1c91bd6a5affd43c5624e929ffbfa1eeb0cc8/README.md) specify Xcode 26. Apple's [Xcode system-requirements table](https://developer.apple.com/xcode/system-requirements) requires macOS 15.6 or newer for Xcode 26; Xcode 15.4 supports Sonoma and supplies Swift 5.10. Therefore the documented current build cannot run on the unchanged 14.5 machine. A binary built elsewhere may still target 14; that is a different, untested proposition. Downgrading the manifest alone is not evidence of a working backport.

**ASR:** [SpeechTranscriber.swift](https://github.com/shubhamsWEB/murmur-app/blob/c9b1c91bd6a5affd43c5624e929ffbfa1eeb0cc8/Sources/VoiceKit/SpeechTranscriber.swift) defaults to English-only Parakeet v2, offers a multilingual mode, and has a separate Hinglish-specific Whisper model. [ParakeetTranscriber.swift](https://github.com/shubhamsWEB/murmur-app/blob/c9b1c91bd6a5affd43c5624e929ffbfa1eeb0cc8/Sources/VoiceKit/ParakeetTranscriber.swift) selects Parakeet Ultra for new multilingual downloads, preserves already-downloaded v3, and caches the loaded model. These are concrete integration choices; the stated 25-language coverage and quality improvements do not establish code-switching accuracy for our UK/RU/EN recordings. Do not select its default English model for this use case.

**Microphone:** the [dictation controller](https://github.com/shubhamsWEB/murmur-app/blob/c9b1c91bd6a5affd43c5624e929ffbfa1eeb0cc8/Sources/VoiceKit/DictationController.swift) wires key-down/key-up handlers and recorder start/stop. [MicRecorder.stopNow](https://github.com/shubhamsWEB/murmur-app/blob/c9b1c91bd6a5affd43c5624e929ffbfa1eeb0cc8/Sources/VoiceKit/MicRecorder.swift) removes the input tap and stops AVAudioEngine, a useful reference. The app also supports latched hands-free interaction, so a strict held-key-only fork must remove/disable that path and test missed key-up, cancellation, focus changes, sleep, and input-device changes. Source comments note that microphone startup can take over a second, especially with Bluetooth; this is not a measured latency guarantee.

**Actions and consent:** [Approvals.swift](https://github.com/shubhamsWEB/murmur-app/blob/c9b1c91bd6a5affd43c5624e929ffbfa1eeb0cc8/Sources/AgentKit/Approvals.swift) defines separate message/click/script/command categories, but supports both whole-task approval and persistent always-allow approval, including messages. [Messaging.swift](https://github.com/shubhamsWEB/murmur-app/blob/c9b1c91bd6a5affd43c5624e929ffbfa1eeb0cc8/Sources/AgentKit/Messaging.swift) implements sends and relies on the caller to have approved. These are useful starting patterns, **not** the required immutable per-send gate. The project advertises a local Ollama command model plus optional Claude/OpenAI text reasoning and direct commands; that direction fits local audio, but this review did not prove a universal allowlist or an unbypassable send gate across browser, scripts, keystrokes, and connectors.

**Reuse candidates:** key handling, audio capture lifecycle, small HUD, ASR adapter interface, and confirmation UI. Keep the MIT notice for copied code. Do not inherit indexing, ambient memory, generated scripts, or broad agent execution merely to get voice input.

## Cursor Voice — compatible declared target, incompatible cloud-audio core

Real repository: [cursorvoice/cursor-voice](https://github.com/cursorvoice/cursor-voice), snapshot `7a9f6d87dc149af11549e34bc17b4afcf0d0382b`, [MIT](https://github.com/cursorvoice/cursor-voice/blob/7a9f6d87dc149af11549e34bc17b4afcf0d0382b/LICENSE). The [build script](https://github.com/cursorvoice/cursor-voice/blob/7a9f6d87dc149af11549e34bc17b4afcf0d0382b/scripts/build.sh) compiles native Swift for `arm64-apple-macos14.0`; compilation and execution on 14.5 were not tested.

Its [Realtime client](https://github.com/cursorvoice/cursor-voice/blob/7a9f6d87dc149af11549e34bc17b4afcf0d0382b/Sources/CursorVoice/Realtime/RealtimeClient.swift) uses the OpenAI Realtime service and an audio engine. This is a cloud voice conversation architecture, not local transcription followed by optional text reasoning. The [coordinator](https://github.com/cursorvoice/cursor-voice/blob/7a9f6d87dc149af11549e34bc17b4afcf0d0382b/Sources/CursorVoice/AppCoordinator.swift) has hold-to-talk press/release hooks, but release deactivates and disconnects the session; it is not evidence of a robust release-then-finish local command pipeline. Wake-word mode is another separately controllable microphone path.

The [ShellRunner](https://github.com/cursorvoice/cursor-voice/blob/7a9f6d87dc149af11549e34bc17b4afcf0d0382b/Sources/CursorVoice/Capabilities/ShellRunner.swift) executes model-supplied text through `zsh -l -c`, using a risky-pattern filter and optional bypass. Its own source acknowledges that a pattern list is incomplete and that per-command confirmation remains the durable fix. This is not an allowlisted executor. The [website](https://cursorvoice.app/) claims inexpensive sessions and screen-aware operation; neither claim proves our $10 cap or mixed-language accuracy. Replacing its audio path and action policy removes most of the advantage of a full fork.

## Samuel — research reference, wrong default architecture

Real repository: [sambuild04/screen-voice-agent](https://github.com/sambuild04/screen-voice-agent), snapshot `895a18e01c6133dd9eef1f8525da9fb200d58542`, [MIT](https://github.com/sambuild04/screen-voice-agent/blob/895a18e01c6133dd9eef1f8525da9fb200d58542/LICENSE). Its [website](https://samuelai.app/) advertises Apple Silicon/macOS 14+, ambient screen/system-audio understanding, cloud Realtime responses, and roughly half-second voice replies. Those are author claims, not independently reproduced M1 benchmarks; its own description says screen-reading and deeper tasks take longer.

The [package manifest](https://github.com/sambuild04/screen-voice-agent/blob/895a18e01c6133dd9eef1f8525da9fb200d58542/package.json) establishes Electron/React/TypeScript, native helper packaging, and Node >=20 for development; it does not itself declare a macOS minimum release. Thus the website's 14+ claim was not independently validated at the packaged-binary level. The [security policy](https://github.com/sambuild04/screen-voice-agent/blob/895a18e01c6133dd9eef1f8525da9fb200d58542/SECURITY.md) explicitly includes system-audio listening, desktop control, dynamically generated/executed TypeScript plugins, and consent/approval flows. It also treats prompt injection and approval bypass as in-scope security issues. Consent mechanisms exist; this is not evidence that every external send requires fresh approval. Ambient sensing, cloud audio, plugin generation, and browser automation are unnecessary scope for the requested first version.

## agent-desktop — possible later action adapter, not an assistant

[vercel-labs/agent-desktop](https://github.com/vercel-labs/agent-desktop), snapshot `b43ac4f6e892ef608f8851428613c4009f0e84c7`, is [Apache-2.0](https://github.com/vercel-labs/agent-desktop/blob/b43ac4f6e892ef608f8851428613c4009f0e84c7/LICENSE). Its [README](https://github.com/vercel-labs/agent-desktop/blob/b43ac4f6e892ef608f8851428613c4009f0e84c7/README.md) describes an accessibility-tree CLI/C library with element references and no model inside. It supplies neither microphone/ASR nor our command-policy/approval layer. It can be evaluated in phase 2 behind a narrow adapter, with snapshots treated as untrusted content and sends still enforced by the host policy.

The [installation documentation](https://github.com/vercel-labs/agent-desktop/blob/b43ac4f6e892ef608f8851428613c4009f0e84c7/apps/docs/content/docs/installation.mdx) lists macOS arm64/x64 and Accessibility requirements. Its [macOS helper build](https://github.com/vercel-labs/agent-desktop/blob/b43ac4f6e892ef608f8851428613c4009f0e84c7/crates/macos/build.rs) defaults `MACOSX_DEPLOYMENT_TARGET` to 10.15, but that alone does not validate the complete release on 14.5. No installation was performed. Direct native app actions are simpler for the first few approved commands.

## What must be demonstrated before implementation choice is final

1. A pinned ASR build loads on macOS 14.5 and transcribes the user's mixed-language samples; language-list support alone is insufficient.
2. Physical mic capture stops on key release, including cancellation/error paths; prewarming models must not prewarm live capture.
3. Measure warm and cold key-release-to-result separately on the M1; report p50/p95 and command success. ≤2 seconds is a target, not an existing-solution fact.
4. Every path to sending resolves to the same per-action approval gate. Do not permit arbitrary shell, AppleScript, JavaScript, plugins, or synthetic Enter to bypass it.
5. A local router handles common commands; complex text-only cloud calls have a hard app-enforced budget and clear refusal/fallback once exhausted.
